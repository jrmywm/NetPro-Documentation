# Server-directed RST proof — 2 October 2026

A controlled, low-rate test verified Policy's generated server-directed TCP RST on the Gateway's routed server path. It is VM-routing evidence, not a physical TAP test or a high-load/loss-free guarantee.

The target was `192.168.31.35:8443` (`netpro-server-proof.test`), with a temporary SNI-only policy using dummy blocked IP `192.0.2.123`. The policy (`d0776817-4cda-4a10-8eab-ec6f57f3039b`) was deleted after testing. The service returned HTTP 200 before and after the block window. During the final block window, a TLS request timed out (`curl` exit 28). Backend TLS logs recorded a write error when the injected server-directed reset interrupted the server-side write; this occurred before the curl timeout.

Early deny attempts returned HTTP 200 because `rp_filter=2` on `all` overrode the `ens38` setting and caused invalid cross-device forwarding. Setting `all=0` and `ens38=0` fixed the path while `ens33` and `ens37` remained at `2`. Captures show server-directed RST sequence `2684819563` at Gateway `ens38`, then NATed from `192.168.31.37` on `ens33`, and at the backend; the backend ACK acknowledged that sequence after the 232-byte ClientHello. Host clocks were offset, so capture timestamps do not establish end-to-end latency.

The Gateway `ens38` catch-all dropped four Policy-generated client-directed RST packets (184 bytes); the `ens37` guard for genuine client-originated RSTs remained at zero. Four server-directed RST packets (184 bytes) passed to the host path. This proves the server-directed path in the captures, not delivery of a client-directed reset. Telemetry baselines were NPB `204359` and Policy `201984`; six new rows included two allow cases, two early ineffective deny cases, and two successful server-RST deny cases. Totals were six TLS inputs/outputs, four RSTs in each direction, and eight Policy transmissions.

The temporary policy was absent from the Policy SQLite database after deletion. Gateway cleanup restored `ip_forward=0`, `ens38` down and non-promiscuous, with reverse-path filtering restored. Final replay verified both forwarding-interface filters empty, no owned iptables rules or active timer, and proof state absent. The listener expired and was cleaned up; backend/PostgreSQL remained active. Final checks verified NPB and Policy active, Policy DB integrity `ok` with four rows, and the client using its direct `ens33` route sourced from `192.168.31.39` with no temporary `/32` route. TRex remains stopped. No production source or startup configuration was changed.

Textual evidence and lab-specific helpers are in [`evidence/server-rst-proof`](../evidence/server-rst-proof/) and [`scripts/server-rst-proof`](../scripts/server-rst-proof/). The packet captures are local-only, gitignored evidence and are not included in the repository commit.
