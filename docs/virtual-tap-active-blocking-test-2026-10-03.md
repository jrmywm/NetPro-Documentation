# Virtual TAP active-blocking validation — failed safety test, 3 October 2026

This test did **not** validate safe or reliable active blocking through the virtual TAP. The passive mirror path remains the safe configuration; do not repeat active reset injection on this shared receive segment without redesign or reviewed loop suppression.

Two TLS allow requests to `netpro-tap.test` succeeded at `16:42:27 UTC`. A temporary SNI-only Policy rule (`2e6ecb4e-8e3b-44ad-aaf7-470cfc7749c1`, dummy blocked IP `192.0.2.123`) was then created and synchronized. For the test only, Gateway `ens38` on the shared `NetPro-RX` segment was brought up/promiscuous and a `pref 110` filter redirected client-destination RSTs toward `ens37`; the TAP monitor `ens36` ingress-drop rule remained active.

At `16:44:08 UTC`, the first blocked phase returned HTTP 200 for one request and curl exit 35 for the other. A retest at `16:44:33` failed both TLS requests with exit 35. During 27 seconds, the return path counted 3,129,472 bytes and 68,032 RST packets. This burst is consistent with Gateway-injected RSTs traversing TAP `ens35`, being mirrored to `ens36` on shared `NetPro-RX`, and repeatedly redirected by Gateway `ens38`; this is a likely feedback loop, not a PCAP-proven packet trace.

Policy telemetry showed reset generation but not dependable blocking: pre-block row `211912` had TLS 2, RST 0/0; blocked rows `212014` and `212038` each had TLS 2 and RST 2/2, despite the escaped first HTTP 200; after allow rows `212121`/`212122` showed TLS 1 and RST 0/0. The created policy was deleted and absent from backend test data and Policy SQLite. Two post-cleanup TLS requests returned HTTP 200. Temporary listeners stopped; forwarding was `0`; the TAP monitor/bridge and NPB/Policy were active. No temporary test policy remains; production policies were unchanged.

Capture attempts failed with permission errors using `-Z netpro`; the capture files had been created by `NETPRO` with mode `0600`, but the exact reason for the permission errors was not established. Resulting zero-byte PCAPs are unusable and were not copied. Text evidence is in [`evidence/virtual-tap-active-test`](../evidence/virtual-tap-active-test/). Next, use a dedicated Policy RST-output/injection segment separate from `NetPro-RX`, or review loop suppression before another active test.
